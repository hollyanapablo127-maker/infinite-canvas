## 2. 用户已确认的产品边界

1. 用户身份只有“管理员”“用户”。统一账号密码登录，不让登录者选择身份；服务端鉴权后展示对应内容。
2. 管理员左侧栏同时包含“管理员分区”和“个人账号分区”，个人分区与普通用户完全一致。
3. 用户独立 API 指平台签发的站内 API Key；上游使用管理员配置的阿里云百炼 API Key。首版不做用户自带百炼密钥。
4. 首版人工管理站内余额：管理员充值、扣减、退款及记录；不接在线支付，不宣称自动原路退回银行账户。
5. 首版站内售价按官方原价初始化，由管理员分别配置每个模型、每个分辨率的售价和站内折扣。
6. 用户上传素材、生成结果分别从上传完成、结果转存完成时起保存 30 天；到期提醒、批量下载纳入首版。
7. 画布结构、提示词、调用与账单记录不随媒体的 30 天到期一起删除。
8. 技术栈由本计划推荐，部署与依赖获取必须适应中国大陆网络；不依赖谷歌浏览器和境外在线服务。

## 3. 必须遵守的开发约束

1. **子智能体仅用于代码审查，不能用于代码开发。** 不向子智能体分配实现、改文件、修复、生成业务代码等工作。本轮调研和计划不启用子智能体。
2. **修复前先分析最佳方案与影响。** 明确根因、至少一个可比较方案、受影响模块与数据、兼容性、回滚方式，以及引入其他故障的可能性；禁止仅消除报错而掩盖根因。
3. **持续维护开发进度。** 每完成一个可独立描述的部分，立即更新 PROGRESS.md；中断前写清已完成内容、剩余工作、文件位置、问题和下一步。
4. **全部功能开发完成后，统一测试和修复。** 功能开发期间不交替开展测试与修复轮次，不提前做真模型试调用、端到端验收或压力测试。发现问题先登记；全部功能完成后进入集中审查、测试、修复、回归。若遇到无法继续开发的阻塞，先说明并询问用户是否调整顺序，不能自行绕开该约束。
5. **用户体验优先。** 从登录到生成、查看费用、再次创作、下载形成连续流程；常用操作直接可见，复杂参数按需展开，不为了减少点击而隐瞒计费或限制，也不为普通操作增加重复确认。
6. **拿不准及时询问。** 影响价格、权益、数据删除、权限、技术范围或付费预算的问题及时记录并询问；未回答不得默认为批准。独立、不受影响的计划工作可继续。

开发阶段可以阅读文档、梳理接口、编写实现和维护需求清单，但不得把“写完代码”标记为“测试通过”。所有正式验证归入集中测试阶段。

## 4. 产品目标与首版范围

目标用户为需要多次尝试、组合素材、比较结果的视频创作者。主体验是可直接创作的无限画布，不做营销首页。

首版应形成完整可用链路：

登录 -> 我的画布 -> 添加素材/生成节点 -> 配置 Wan 3.0 -> 查看费用 -> 提交 -> 后台生成 -> 结果自动入画布和资产库 -> 播放/对比/继续编辑 -> 下载与到期管理。

首版必须包含：

- 两个 Wan 3.0 模型及官方全部参数、素材类型、允许组合、编辑与延长能力。
- 个人画布、资产库、模型广场、任务与使用记录、余额流水、用户 API 管理、公告和账号设置。
- 管理员仪表盘、模型定价、公告管理、用户与余额、百炼 API 管理、全站使用记录、系统设置和操作审计。
- 持久化任务、余额预占与结算、上游渠道独立成本统计、30 天资产生命周期、断网和刷新恢复。
- 编辑草稿自动保存、撤销重做、结果分支、历史参数复用、失败原因与明确恢复动作。

后续扩展而非首版承诺：其他模型供应商、在线支付、多人实时协同、公开作品社区、团队空间、专业多轨剪辑、移动原生客户端。不能因这些扩展推迟 Wan 3.0 的完整适配。

## 5. 页面与权限

### 5.1 登录与注册

- 单一登录页：账号、密码、登录、忘记密码；不出现身份选择。
- 登录后读取服务端身份和权限。普通用户进入个人工作台，管理员首次进入仪表盘；以后恢复最近访问页面。
- 未登录访问具体画布时，登录后回到原目标；无权访问显示明确结果，不泄露其他用户资源。
- 注册入口根据系统开关显隐，服务端同步强制执行；邮箱验证码开关决定注册流程。
- 邮箱验证开启前必须配置国内可用的邮件服务。验证码有有效期、发送间隔、错误次数和消费状态；关闭验证不等于关闭基础防滥用。
- 邮箱重置密码限已验证邮箱；无已验证邮箱的账号通过管理员重置，不能仅凭未验证邮箱取回账户。
- 首个管理员通过部署时的一次性初始化方式创建，不提供默认万能账号；自助注册不能提交管理员角色。
- 禁用账号、修改密码或敏感权限后撤销相关会话。

## 6. 无限画布体验

### 6.1 工作区布局

- 顶栏：项目名称、保存状态、撤销/重做、任务入口、余额、导出。
- 左侧：可收起的素材/节点入口；全局侧栏在画布中允许收起，给创作留出空间。
- 中间：无限平移缩放的画布，支持缩略导航、适合全部、定位选中节点、网格对齐。
- 右侧：选中节点属性面板，固定结构；常用参数置顶，高级设置折叠。
- 任务在画布节点中显示简明状态，全局任务抽屉集中管理；不会因打开多个节点而增加上游查询频率。

### 6.2 节点与连线

| 类型 | 操作与语义 |
| --- | --- |
| 文本/提示词节点 | 自由文本、分镜草稿、素材引用；连接到生成节点或直接编辑其提示词 |
| 图片节点 | 预览，指定为首帧/尾帧/参考图；裁切或去透明作为显式派生操作 |
| 视频节点 | 播放、元数据、截取合规片段、提取首/尾/指定帧、用作参考/编辑/延长 |
| 音频节点 | 播放、时长、片段截取、用作参考音频 |
| 文件节点 | 文件名、类型、大小、可获得的页数、下载；无需支持浏览器内编辑全部格式 |
| 网页节点 | URL、公开可访问状态、可用的标题信息；不执行网页内的脚本 |
| Wan 3.0 生成节点 | 完整参数、素材端口、报价、提交、状态、结果版本 |
| 备注/分组 | 组织分镜、锁定、命名、颜色、折叠；不参与模型请求 |

连线有明确类型和端口语义；也提供“选择已有素材”替代拖连线，键盘与触屏可完成同一操作。

先完成连接，不自动发起付费调用。编辑上游素材后，下游已生成结果标记为“基于旧配置”，保留原参数快照；重新执行须用户主动触发。

批量运行和运行到此节点属于站内任务编排：按依赖顺序执行，禁止环路；显示总预计金额及最高冻结额；上游失败时下游等待处理。每个生成节点仍然对应上游单独一次调用，每次输出一个视频。

### 6.3 完整创作流程

1. 创建空白画布，或从内置场景模板开始。模板包含实际可编辑节点，不额外调用语言模型。
2. 拖入文件、粘贴图片、输入 URL，或从资产库选择；立即显示上传进度、大小和格式问题。
3. 选择文生、首帧、首尾帧、全模态参考、视频编辑、视频延长。模式仅是站内配置方式，不伪造上游 mode 参数。
4. 为素材分配角色并排序；图、视频、音频分别编号。使用稳定素材 ID 绑定引用，再编译为官方“图1/视频1/音频1”；删除被引用素材时定位引用，不静默串号。
5. 填写提示词；可以展开分镜、台词、BGM、风格、负向清单等辅助编辑，最终合并为 prompt；随时可查看和修改最终文本。
6. 设置模型版本、分辨率、宽高比、固定/智能时长、有声开关；高级区保留随机种子、智能改写、水印。
7. 在生成按钮附近显示模型单价、计费秒数、预计费用、最高冻结额及可用余额。音频开关变化不改变价格。
8. 提交后节点显示排队/生成状态，允许继续编辑其他部分或离开页面。上游不提供准确进度时不伪造百分比。
9. 成功后自动转存，显示“保存中”直至资产可用；结果按版本挂在节点旁，不覆盖输入素材或旧版本。
10. 结果支持播放、并排对比、下载、复用参数、再次生成、转为编辑/延长节点。再次生成是新付费任务，明确显示新报价。

生成 30 秒的视频不能直接再作为参考输入，因为参考视频合计最多 15 秒。应提供不覆盖原视频的截取流程，并重新预览尺寸、帧率和费用。

### 6.4 保存、撤销与恢复

- 画布结构、连线、素材引用、参数草稿和视口保存到服务端；浏览器 IndexedDB 保存短期未同步草稿。
- 稳定节流的自动保存、明确“保存中/已保存/离线待同步/保存失败”状态；刷新后恢复。
- 使用版本号和乐观并发控制防止多标签覆盖；冲突提供选择保留版本或复制画布，不自动抹除草稿。
- 撤销重做针对编辑动作，不撤销已经提交的上游任务和账务。
- 删除正在运行的节点必须说明任务仍在运行；用户可选择保留任务记录并从画布移除，或在可取消时申请取消。
- 画布复制共享本人资产引用，不重置资产到期时间，不自动复制密钥或执行任务。
- 删除画布和删除源资产分开；显示其他画布引用情况。回收站不突破媒体原定到期时间。

## 7. 模型广场与定价呈现

### 7.1 页面内容

首版列出 Wan 3.0 标准版、Wan 3.0 高速版两项，不用虚构模型充数。每项展示名称、官方模型 ID、北京地域、能力、支持规格、可用状态和全部价格档位。

桌面采用紧凑的模型列表与对比价格表；移动端每个模型一个展开项。模型的真实示例视频/封面可本地托管或置于国内 OSS，默认不自动播放；正式示例使用自有或明确许可素材，官方演示链接仅作为研究参考。

### 7.2 六档初始站内售价

| 模型 | 480P | 720P | 1080P |
| --- | --- | --- | --- |
| wan3.0-video | 0.30 元/秒 | 0.60 元/秒 | 1.20 元/秒 |
| wan3.0-video-prime | 0.45 元/秒 | 0.90 元/秒 | 1.80 元/秒 |

上述为用户已确认的初始化规则，不代表实际阿里云账单成本。

- 主显示“站内单价”，清楚标注元/秒。
- 有站内折扣时显示对应的官方原价、站内价、折扣数值和生效范围。
- 官方活动与站内折扣分别标注。当前标准版官方页面标有限时七折，活动是否有效以上线时控制台为准；不自动向用户承诺跟随官方活动。
- 站内折扣以当前档位官方原价为基准，折数 = 站内单价 / 官方原价 × 10；无优惠不贴优惠标签，溢价不得显示成折扣。
- 不能只展示“最低价起”而把其他分辨率放进难找的弹窗。
- 价格试算支持选择模型、分辨率、参考视频秒数和输出秒数；有视频输入时同时显示两部分计费。
- 智能时长显示费用范围与最大冻结金额；不把默认 5 秒当作最终实扣时长。
- “加入当前画布”直接插入节点；无画布时可新建或选择已有画布，避免丢失选定规格。

目前 Wan 3.0 是模型版本 × 分辨率的规格分档，并非按月累计用量阶梯，也不是 Token 阶梯。首版数据结构保留定价维度，但不展示不存在的规则。

### 7.3 管理员定价

每个档位独立设置官方参考原价、站内售价或折扣、版本、生效时间、启用状态。售价与折扣联动计算，不能同时填出矛盾值。

变更前展示六档前后对比和代表性任务试算；发布后新任务使用新版本，已提交任务按快照结算。历史记录不得随改价回算。

## 8. 用户密钥与百炼 API 管理

### 8.1 用户站内 API

- 每用户独立调用主体；支持多个命名密钥，创建时显示一次明文，此后仅显示前缀/尾号。
- 站内密钥只存不可逆摘要，随机强度充足；不把上游百炼密钥发送给用户。
- 创建、禁用、撤销、轮换、有效期、模型限制、日/月金额上限、速率限制；列表显示最近使用、累计消费。
- 对外调用统一站内鉴权、报价、余额、队列与记录。网页通过登录会话映射到本人调用主体，不要求用户每次复制粘贴密钥。
- 网页与对外 API 调用记录保留来源以及所属站内凭证标识；密钥撤销后仍保留历史统计。
- 对外开放异步创建、查询、取消、余额、模型及价格、上传与下载接口，生成 OpenAPI 使用文档。站内价格和限制返回给调用方，上游成本不返回。
- 站内幂等键区分“重复发送同一任务”和“主动再次生成”；再次生成必须采用新幂等键。

### 8.2 上游百炼 API

每条配置独立保存：名称、主账号分组、WorkspaceId/API Host、北京地域、加密密钥、允许模型、优先级/权重、启停、渠道预算、告警阈值、成本倍率、备注。

- 固定北京域名白名单，WorkspaceId/API Host 格式校验；不能由用户请求指定任意上游地址。
- 密钥加密存储，运行时按需解密；管理员列表也不回显完整密钥。
- 按每条 API 统计任务数、成功/失败、输入/输出秒数、用户扣款、估算成本和利润。
- 同一主账号下多把密钥共享模型配额，不能通过轮换密钥假设绕过限流；主账号分组是调度的必要字段。
- 调度采用健康状态、启用模型、渠道预算及账号配额；冻结预算后绑定渠道与配置版本。
- 创建成功后任务固定关联上游渠道和业务空间。渠道被停用或轮换时保留旧凭证版本以处理在途任务，完成后再清理。
- 明确未受理的错误可以按策略重排；创建超时且是否受理未知时禁止盲目换渠道重发，进入待核实。
- 不依赖上游任务查询权限做租户隔离；上游主账号可查询其他 Key 提交的任务，站内仍必须按用户所有权限制。

## 9. 钱包、计费、成本与退款

### 9.1 计费公式

设 P 为任务提交时的站内单价，D 为供应商成功结果返回的 usage.duration，M 为绑定渠道的成本倍率：

- 计费时长 D = 实际输入视频秒数 + 成功输出视频秒数。
- 用户扣费 U = round(P × D, 6)，单位元。
- 渠道估算成本 C = round(U × M, 6)。
- 估算毛利 = 用户模型净收入 - 估算成本；退款单独进入净收入统计。

1x 表示估算成本等于本次用户模型扣费，0.5x 表示其一半。倍率不是官方售价倍率，也不是官方折扣。依照用户要求，不能把倍率基准改成阿里云目录价。

估算成本、官方参考成本、阿里云实际出账金额分列；没有实际账单对账数据时不标成“实际成本”。官方免费额度与优惠属于上游账户权益，不默认给每位站内用户赠送 30 秒。

### 9.2 资金与精度

- PostgreSQL NUMERIC 或整数微元记账，应用层使用十进制定点库，不用浮点数直接运算余额。
- 建议内部以 0.000001 元为最小单位，采用明确的四舍五入规则；页面默认两位，细账能查看精度更高的数值。
- 保留原始秒数、原始 usage、单价快照、倍率快照、计算过程及舍入结果。官方没有明确逐秒取整规则，不擅自向上取整。
- 余额调整采用追加流水和冲正，不直接改历史流水；每笔必须有用户、管理员、金额、类型、原因、关联业务和前后余额。
- 人工充值不计入模型收入；冻结不等于消费；账户间不共享余额。
- 使用数据库事务、行锁/条件更新和唯一业务键保证并发不会重复扣款或透支。

### 9.3 预占与结算流程

1. 服务端验证参数和素材，生成带版本与有效期的报价。
2. 用户提交时校验报价、可用余额和密钥限额；原子创建任务、冻结预算和待发送记录。
3. 固定时长按输入合计 + 目标输出估算；智能时长按最高合计 30 秒预占。前端明确展示冻结上限，用户可以改为固定时长。
4. 队列工作进程领取任务；成功取得 task_id 后保存绑定关系。
5. 成功终态获取 usage，按价格快照扣实际金额、释放余款，一次且仅一次。
6. 明确失败或确认取消的任务释放冻结，不收取模型生成费；网络超时/UNKNOWN 不直接等同失败。
7. 缺失 usage、用量异常、实际金额高于预占等情况进入待核对，不能自动超额扣用户余额；恢复流程与异常支出由管理员处理。
8. 结果下载失败属于资产保存问题，不把已成功计费任务当作模型失败重发。优先重试转存；彻底无法交付按人工退款处理，并保留上游成本。

状态不能完全依赖 Redis。数据库持久化、事务发件箱、任务租约、重启恢复和定期对账共同保证可恢复性。

### 9.4 人工操作必须区分

| 操作 | 余额方向 | 要求 |
| --- | --- | --- |
| 充值 | 增加 | 登记原因和外部收款凭据/备注，可记录线下来源 |
| 人工扣减 | 减少可用余额 | 不可动用冻结金额，不可改成负数 |
| 调用退款 | 退回站内余额 | 关联原扣费，累计退款不得超过可退额 |
| 充值退回/线下退款登记 | 减少对应可用余额 | 记录站外退款凭据，系统仅记账，不自动完成外部资金转账 |
| 冲正 | 原业务的反向流水 | 关联原操作，防重复，保留原始记录 |

涉及金额的表单显示操作类型、影响后的余额和原因，提交采用幂等处理。退款不自动抹去已经发生的上游成本。

## 10. 资产与 30 天临时存储

### 10.1 范围和计时

用户已确认：上传素材从上传成功起算，生成结果从成功转存站内 OSS 起算，分别保留 30 × 24 小时。数据库统一存 UTC，页面展示 Asia/Shanghai 对应时间与剩余天数。

- 每个资产保存 created_at、available_at、expires_at、状态、归属、类型、大小、媒体元数据和来源。
- 缩略图、波形、预览转码、截取派生文件与对应原资产建立关联，纳入清理清单。
- 在站内重复引用、收藏或复制画布不刷新原资产到期时间；明确重新上传的文件可作为新资产记录。
- 不把画布结构、提示词、任务账单、密钥历史统计放进媒体清理规则。
- 在新任务提交前检查素材是否有效及剩余可用时间，快到期时要求重新上传或调整任务，不悄悄延长保存承诺。

### 10.2 转存与下载

- 阿里云结果链接仅有效 24 小时；任务成功后立即转存北京 OSS，校验文件大小、可读性和校验值，保存失败自动重试并告警。
- 私有 Bucket，通过鉴权签发短期下载/预览 URL；不保存永久公开链接，不用阿里云临时文件空间承载 30 天资产库。
- 用户可按日期、类型、画布、标签、即将到期筛选；支持重命名、批量添加到画布、逐项下载和批量打包。
- 大批量下载异步打包，显示真实状态；打包文件有独立短期有效期，不能让到期媒体借导出包永久存续。
- 生成结果“收藏”只表示整理，不代表永久保留。

### 10.3 到期处理

- 站内提前 7 天、3 天、1 天提醒，支持合并通知和已读；用户选择接收时可向已验证邮箱发送摘要。
- 到期时服务端禁止新访问并将资产标记为过期；计划清理原件、缩略图、派生文件、临时 ZIP、缓存和历史对象版本。
- 清理采用到期检查、任务引用核对、幂等删除和失败重试。OSS 生命周期仅作为兜底，不能承诺它在到期那一秒立即物理删除。
- 签名 URL 的有效期不超出资产到期时间；缓存 TTL 同步受限。
- 画布保留“素材已到期”占位及参数记录，提供重新上传/替换，不让整张画布打不开。
- 资产回收站和备份恢复不得绕过 expires_at；元数据恢复后仍要执行到期检查。
- 账单不保存完整 Base64 及带签名的永久链接，避免日志无意保留已到期媒体。

## 11. 管理员页面

### 11.1 仪表盘

- 总用户数、今日新增、今日活跃、今日生成次数、排队/运行/失败数量、成功率。
- 今日模型收入、退款、冻结资金、估算成本、估算毛利；充值总额单独展示。
- 7/30 天趋势、按模型/分辨率消费排行、渠道费用排行、资产存储量和即将到期量。
- 可筛选日期，所有“今日”按北京时间 00:00 至次日 00:00；卡片可下钻到相同筛选条件的列表。
- 任务按创建时间统计、收入按账务生效时间统计，口径明确；成本标注估算/已对账。

### 11.2 用户管理

搜索、分页、注册时间、邮箱验证状态、角色、启停、可用/冻结余额、累计消费、最近活跃；用户详情展示其调用与资金流水。充值、扣减、退款均使用上述账务流程。

账号冻结只禁止新操作，不中断已产生上游费用的任务结算和结果保存。不得删除最后一个可用管理员；敏感操作需重新认证并审计。

### 11.3 公告管理

草稿、预览、立即/定时发布、结束时间、置顶、普通/重要级别、面向所有人或指定身份、修改版本、撤回。渲染富文本需清理危险内容。

普通公告通过顶栏入口与列表呈现；影响调用的维护公告放在相关页面，避免每次登录重复弹窗。

### 11.4 全站使用记录

字段包括用户、站内 Key 标识、网页/API 来源、模型、分辨率、任务类型、输入/输出/计费秒数、售价、折扣、实扣、退款、上游渠道、倍率、估算成本、实际账单成本（如有）、请求 ID、任务 ID、状态、耗时和转存状态。

支持多条件筛选、分页、详情和异步导出。用户版共用底层查询能力，但采用专门的字段白名单，排除所有成本与上游密钥信息。

### 11.5 系统设置

站点名称与图标、开放注册、注册邮箱验证、邮件服务、用户默认限额、并发策略、素材大小与存储配额、30 天保留策略、公告、维护模式、国内 OSS 配置、日志与备份设置。

设置有版本和审计。缩短已有用户资产保留期不得立即批量删除存量数据，必须先向用户确认变更策略并完成通知。修改默认值不回写已提交任务快照。

## 12. 技术方案

选择模块化单体 + 独立异步 Worker，先保持部署与维护简单；长期任务和媒体处理不放在一次 HTTP 请求内执行。

| 层级 | 推荐方案 | 选择原因 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 适合交互密集的工作台，无需营销页 SSR |
| 画布 | React Flow / @xyflow/react | 成熟节点、端口、缩放和平移基础能力 |
| UI | Tailwind CSS + 基于 Radix 的组件 + Lucide | 统一表单、抽屉、菜单、键盘行为与工具图标 |
| 前端状态 | Zustand + TanStack Query | 分离画布本地编辑态与服务器数据 |
| API | Node.js 当前维护的 LTS + NestJS | 模块化鉴权、账务、任务和管理接口 |
| 数据库 | PostgreSQL + Prisma | 事务、定点金额、迁移与所有权关系 |
| 队列 | Redis + BullMQ | 生成调度、轮询、转存、清理、导出任务 |
| 媒体存储 | 阿里云 OSS 华北2（北京） | 国内可访问，与模型地域一致 |
| 媒体探测 | FFprobe/FFmpeg，必要时图像处理库 | 元数据、缩略图、截取、首尾帧提取 |
| 邮件 | 国内可用邮件服务，通过统一适配器 | 验证码、账户恢复和可选通知 |
| 部署 | Linux + Docker Compose + Nginx | 首版部署可控，后续独立扩容 Worker |
| 集中测试 | 单元/集成工具 + Playwright 的 Microsoft Edge 通道 | 不依赖谷歌浏览器 |

具体版本在开发阶段开始时统一锁定。运行所需包、字体、图标、脚本均打包本地托管；不得在页面引入 Google Fonts、境外 CDN、境外验证码或必须境外连接的服务。依赖可从合规国内镜像获取并保留锁文件及完整性校验。

工作区当前没有应用代码或既定框架，因此此方案为本项目的推荐基线；若部署方已有运维约束，应在搭建前调整，避免后期换栈。

### 12.1 模块划分

账户与权限、个人 API、模型目录、价格与报价、钱包与流水、上游渠道、Wan 适配器、生成任务、画布、资产、公告、系统配置、审计与统计。

前后端共用参数类型与能力描述，但后端独立强制验证。价格只由服务端计算；前端显示不作为结算依据。

### 12.2 核心数据模型

| 实体 | 主要职责 |
| --- | --- |
| users / sessions / email_verifications | 账号、角色、验证和会话撤销 |
| user_api_keys | 用户密钥摘要、限额、来源、状态 |
| provider_accounts / provider_credentials / credential_versions | 上游主账号配额组、独立 API、密钥轮换 |
| models / model_capabilities / price_versions | 模型能力及六档价格的版本 |
| wallets / wallet_ledger / reservations | 可用和冻结余额、不可变流水、预算预占 |
| projects / canvas_revisions | 画布内容、视口、版本和保存冲突 |
| assets / asset_derivatives / asset_references | 资产归属、元数据、30 天到期与引用 |
| generation_tasks / task_attempts / task_events | 参数快照、上游关联、状态、用量及错误 |
| workflow_runs / workflow_steps | 显式付费的依赖运行与批次状态 |
| usage_records / cost_entries / refund_records | 用户费用、渠道估算/实际成本和退款 |

| settings_versions / audit_logs | 配置版本和管理员审计 |

所有个人业务表建立 user_id 或可追溯的所有权关系；涉及钱包与任务的唯一键和事务约束在设计时明确。保存完整请求语义，但不保存密钥和不必要的敏感 URL。

### 12.3 站内接口族

- /api/v1/auth：登录、注销、注册、验证、密码恢复、会话。
- /api/v1/models、/quotes：模型列表、档位、能力、报价。
- /api/v1/projects：个人画布、版本、保存、复制、恢复。
- /api/v1/assets：上传授权、校验、列表、签名预览、批量导出。
- /api/v1/generations：创建、查询、取消、结果、历史版本。
- /api/v1/workflow-runs：明确授权的批量/依赖执行。
- /api/v1/api-keys、/wallet、/usage、/announcements：个人管理。
- /api/v1/admin/*：定价、用户资金、上游渠道、统计、公告、设置、审计。

网页会话和个人 API Key 最终进入相同业务服务及账务逻辑，防止两套扣费规则分叉。

## 13. 任务可靠性与安全边界

- 状态至少区分草稿、校验中、站内排队、提交中、提交结果待核实、上游排队、上游生成、结果转存、成功、失败、取消中、已取消、待人工处理。
- 生成状态、存储状态和结算状态分别保存；不能用一个“失败”吞掉不同故障。
- 按主账号 + 模型管理生成速率和并发，按主账号管理查询请求；当前文档两模型均为 5 RPS、5 并发，查询 20 RPS，上线按实际配额核对。
- 通常每约 15 秒查询，由后台统一轮询并退避；网页通过 SSE 或站内轮询读取缓存的任务状态，不直接查询百炼。
- 收到结果先确认数据库中该任务与用户、渠道的关联，再保存用量与结算。可后续接事件通知，但通知后仍查询官方结果核实。
- 创建请求的上游幂等能力未在 Wan 文档中保证；不能声称“绝对只提交一次”。提交超时进入待核实队列，保留证据、避免重复费用。
- 只支持取消未开始处理的 PENDING 任务；RUNNING 不显示可成功取消的承诺。删除画布节点不等同取消。
- URL 导入防 SSRF：拒绝内网、环回、链路本地、危险协议和重定向绕过；限制下载体积、超时、内容类型及 DNS 解析目标。
- 用户上传文件按真实签名探测类型；媒体解析隔离执行，限制资源与时间；文档不运行宏，网页不执行脚本。
- 登录采用安全密码摘要、HttpOnly/Secure/SameSite 会话、CSRF 防护、登录限流；审计与日志脱敏。
- 成本、完整上游错误、内部渠道信息不写入用户可读事件流、导出文件或接口。
- 备份覆盖数据库、账务和配置；恢复必须保留幂等约束及到期语义，不能让已扣款任务重新扣费。

## 14. 视觉与体验基线

- 主色以中性白/灰与石墨色构成工作界面，少量青绿用于主操作，独立琥珀/红色表示待处理/错误，避免单一色相铺满页面。
- 编辑器优先内容可读性，运营管理页优先表格扫描效率；不采用超大标题、宣传 Hero 或整页浮动卡片。
- 中文使用系统字体栈或国内自托管字体，字号不按视口宽度缩放；普通页面文字与表格保持稳定层级。
- 页面级区块用清晰分隔与留白；重复模型/资产项可使用不超过 8px 圆角的卡片，不层层嵌套。
- 工具动作使用图标和可访问名称/提示；数值用输入或步进器，二元状态用开关，模式用分段/选择控件。
- 用户可明确看到焦点，键盘可访问；表单错误贴近对应字段，金额和任务状态不能只用颜色区分。
- 媒体使用固定宽高比、占位和按需加载；不可见节点停止视频播放。大量节点采用可见区域渲染，避免一次加载全部原视频。
- 桌面优先精细创作；移动端保留浏览、参数修改、提交、下载和记录管理，面板切为抽屉，提供不依赖拖动的操作。
- 低余额、渠道不可用、维护、离线、媒体失效、权限不足、无结果、请求待核实都设计对应状态及可执行下一步。

## 15. 分阶段开发与统一验收

详细任务及权重见 PROGRESS.md。建议顺序：

1. P0：冻结需求、能力矩阵、数据与接口契约、关键页面结构，更新待确认事项。
2. P1：工程基础、账户鉴权、双分区导航、设置与审计骨架。
3. P2：模型与价格、用户密钥、百炼渠道、钱包流水与预算规则。
4. P3：Wan 完整适配、异步任务、调度、用量结算、取消和恢复逻辑。
5. P4：资产上传、解析、转存、30 天生命周期、下载与导出。
6. P5：无限画布、全部创作模式、参数表单、连线、历史和自动保存。
7. P6：模型广场、个人账单/记录/API、完整管理员页面与统计。
8. P7：补齐所有页面状态、响应式、部署与运维说明，核对首版范围；达到“功能开发完成，尚未统一验收”。
9. P8：统一代码审查、自动化/人工/真模型测试、安全与资金并发测试。
10. P9：统一修复、针对影响范围回归，完成发布验收与交接。

P1-P7 不开展分模块测试修复轮次；P8-P9 才进入集中验证与修复。代码审查子智能体只在代码存在且进入审查阶段时使用，最终修复由主开发执行。

不虚报固定工期。首次环境与依赖准备完成后根据实际规模细化工作日估算；用完成比例、任务证据和阻塞项持续衡量进度。

## 16. 完成标准

- WAN3_SPEC.md 中每项能力、参数、组合和响应字段有实现位置及集中验收结果。
