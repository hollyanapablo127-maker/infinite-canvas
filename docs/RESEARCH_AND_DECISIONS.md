## 2. 补充体验调研及取舍

| 观察/依据 | 纳入本项目的设计 | 取舍理由 |
| --- | --- | --- |
| S10 无限画布可组织不同文件和创意 | 图片/视频/音频/文档/网页/提示词放在同一创作空间 | 减少跨页面复制和重复上传 |
| S10 模板和故事板/用户旅程用途 | 可编辑的模式模板、分镜分组、流程内连续操作 | 新用户能开始，熟练用户仍可自由组合 |
| S10 版本管理与素材整理场景 | 结果分支、参数快照、并排对比、资产标签 | 视频生成通常需反复试验，不能覆盖原成果 |
| S10 多人协作 | 暂不纳入首版 | 用户当前需求是账号隔离与个人创作，协作会扩大权限及冲突处理范围 |
| S08 多模态引用独立编号 | 稳定素材引用与提交前编号编译 | 防止调整素材顺序后提示词引用错误 |
| S08 提示词结构 | 可选分镜、台词、声音、风格编辑，最终文本可见 | 不迫使用户填写冗长表单，不另接语言模型 |
| S09 生命周期异步清理 | 应用到期访问控制 + 主动清理任务 + OSS 兜底 | 到期体验不受 OSS 扫描时间影响 |
| S06 异步任务和有限取消 | 全局任务中心、后台恢复、取消条件明确 | 刷新不丢任务，不给用户虚假的取消承诺 |
| S03 实际输入+输出计费 | 生成前完整试算、智能时长预算、实扣拆分 | 避免参考视频产生用户未预期费用 |

上述是有来源的参考与本项目设计选择，不是对竞品性能、全部功能或服务承诺的背书。

UI/UX 本地技能查询返回了通用企业工作台风格，但同时包含与本项目不合适的营销 Hero 和境外字体建议。已排除这些部分；视觉方案按实用创作工具重新限定为内容优先、紧凑信息、稳定布局和本地字体，不将检索结果机械写入产品。

## 3. 用户确认记录

| 决策 ID | 事项 | 用户答复 | 影响 |
| --- | --- | --- | --- |
| D01 | 用户独立 API 含义 | 平台给每个用户发独立站内 API Key，底层使用管理员配置的阿里云 API | 两层密钥；统一资金和上游调度 |
| D02 | 首版资金入口 | 只做管理员人工充值、扣减和退款记录 | 不接支付网关，不假装已完成外部资金退款 |
| D03 | 技术栈 | 没有既定要求，由主智能体推荐 | 推荐 React/Vite/NestJS/PostgreSQL/Redis/OSS |
| D04 | 初始站内售价 | 先采用官方原价，站内折扣由管理员配置 | 六档价格按原价初始化，官方活动独立显示 |
| D05 | 30 天资产范围 | 上传素材和结果分别起算，画布结构、提示词与账单保留；有提醒和批量下载 | 按资产生命周期清理，不删除整个项目或账务 |

用户原始明确要求还包括：两种身份、统一登录、管理员双分区、公告、用户管理、单 API 成本倍率和统计、使用记录、系统注册/邮箱开关、仪表盘、用户成本不可见，以及六条开发约束。这些不是待确认事项。

## 4. 文档差异与处理决定

| 编号 | 差异/歧义 | 本计划处理 | 后续核实 |
| --- | --- | --- | --- |
| R01 | 通用视频价格段落说输入不计费，Wan 3.0 专节说输入+输出计费 | 采用更具体的 Wan 专节 | 真实 usage 和账单核对 |
| R02 | 原价页顶部说活动看控制台，但 Wan 标准版表格写限时七折 | 分开保存原价与活动备注；站内按用户选择原价初始化 | 上线前核对控制台活动、资格和有效期 |
| R03 | 分类上限 10 图+5 视频+5 音频，加文件会达 21；指南说总上限 20 | 分类限制和全局 20 上限同时执行 | 极限组合集中验证 |
| R04 | 指南简表未列 key/pages/numbers，API 完整表列出 | 采用 API 完整 12 格式清单，不擅自删减 | 集中验证实际接收与页数处理 |
| R05 | API 对 last_frame 有说明，但合法组合只列首帧与首尾帧 | 不开放单独尾帧模式 | 只有官方明确更新才扩展 |
| R06 | 延长文字说明 duration 是最终输出总时长，示例有通用 duration=5 | 采用说明语义；同时展示输出和新增秒数 | 真模型延长与计费响应核实 |
| R07 | API 延长段写需 adaptive，使用指南写建议 adaptive | 延长预设使用 adaptive；参数 Schema 仍完整；非自适应延长需验证后明确行为 | 实测及官方后续说明 |
| R08 | 通用异步文档示例 tasks{task_id} 缺少斜杠，Wan 查询接口有斜杠 | 查询按 Wan 正式路径；取消路径待集成核对 | P8 取消用例 |
| R09 | 查询时间字段未标时区 | 保存原始文本和归一化时间，不擅自覆盖 | 真实任务创建时刻对照 |
| R10 | 秒数支持 float，但未明确计费取整和 MB 的字节单位 | 按原始 usage 定点计算，不向上取整；大小保守按十进制 MB | 实账与边界验证 |
| R11 | 临时 OSS URL 绑定模型和主账号 | 生产优先站内 OSS，临时格式需要绑定来源，不任意跨渠道 | 北京域名与特殊 Header 联调 |
| R12 | 同主账号可查询其他 Key 任务 | 本地强制 user_id 权限；每条上游 Key 统计靠站内提交绑定 | 越权测试 |
| R13 | Wan 请求未声明创建任务幂等键 | 本地幂等防重复；上游超时进入待核实，不盲目重提 | 模拟响应丢失与真实可用对账能力 |
| R14 | 官方参考生视频 curl 示例包含未转义的内层引号 | 使用结构化 JSON 序列化，不复制无效示例文本 | 契约校验 |
| R15 | API 只回 orig_prompt，没有保证返回实际随机 seed 或改写后 prompt | 历史仅展示实际可得字段；不伪造“最终 seed/改写文本” | 响应字段检查 |
| R16 | OSS 生命周期非精确即时删除；版本与 ZIP 可能残留副本 | 到期先关闭应用访问，后台清理所有副本，OSS 兜底 | 加速时间测试与测试 Bucket 演练 |

R07 涉及“完整可选参数”与“延长建议限制”的边界：底层保留 ratio 的全部枚举，不悄悄丢弃用户设置；开始实现延长控件前将该差异向用户说明，若要以非 adaptive 作为首版延长操作，需先明确产品策略及官方支持情况。
