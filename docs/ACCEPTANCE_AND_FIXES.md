# 统一验收与修复规范

版本：v1.0；日期：2026-09-30。  
状态：本地集中验收已执行；此文件保留完整验收标准，实际证据与尚未执行项见 ACCEPTANCE_REPORT.md。  
适用阶段：全部首版功能开发完成后的 P8-P9。

## 1. 执行顺序与边界

遵循用户要求：P1-P7 集中实现全部功能，P8-P9 统一审查、测试与修复。不得在开发中穿插逐模块测试修复循环。开发过程中观察到的问题先登记，不冒充已验证结论。

完成实现清单后，固定候选版本和测试环境，再集中编写/整理测试、准备样本并执行。P8 收集问题，P9 按根因和依赖集中修复；修复完成后执行必要回归，不必为完全无关、未改动的模块重复所有昂贵模型调用。

如阻塞导致统一测试不能继续，可以在 P8-P9 内先集中修复该阻塞再继续测试，这仍属于全部开发完成后的统一验证阶段。不得为了“进度 100%”跳过失败项。

## 2. 进入统一验收的条件

- P1-P7 全部任务完成实现，具有具体文件位置和接口。
- WAN3_SPEC.md 每个 ID 已填写实现映射，全部能力可从网页到达。
- 没有用静态列表、模拟成功、不可用按钮代替正式首版功能。
- 价格初始值和 30 天存储政策与用户确认一致。
- 测试数据库、持久任务队列、资产目录与生产资源隔离；首版不依赖 Redis。
- 准备管理员、用户 A、用户 B、禁用账号以及不同限额的 API Key。
- 准备同主账号多 Key、不同主账号的渠道配置样本；模拟与真实密钥分开。
- 明确真实模型调用预算、可用北京凭据与 WorkspaceId。未取得预算和凭据时完成其余测试，真实验收标记为待完成，不能伪造通过。
- 未将真实密钥、邮件验证码、签名 URL 或私有媒体写入代码仓库。

## 4. 参数与素材边界用例

每项均测试“边界前、边界值、边界后”，失败消息指向具体素材或字段。

- prompt：空白、中文、英文、多行、Unicode、19999/20000/20001 字符；media 可满足条件必选，但文生不可空。
- duration：-2、-1、0、1、2、5、30、31、小数和字符串；有视频输入时重新计算可选上限。
- seed：-2、-1、0、2147483647、2147483648、小数；布尔参数不接受字符串冒充。
- 所有 resolution、ratio 枚举与未知值；parameters 省略和逐项省略的默认值。
- 每类媒体数量：0、1、上限、上限+1；参考总数 19/20/21；file/link 同时出现。
- 首尾帧与参考音频等非法混用；只尾帧；模式切换后遗留不兼容媒体。
- 图片：240/8000 像素边界、8:1 与超过值、透明 PNG、真实 WEBP/BMP/JPEG，以及损坏文件。
- 视频：1/15 秒、合计 15 秒、15/16fps、240/4096 像素、8:1、100MB、可变帧率和损坏容器。
- 音频：1/15 秒、合计 15 秒、15MB、wav/mp3 和伪造扩展名。
- 文件：全部 12 种格式，50/51 页、100MB 边界、加密/损坏文件；页数无法可靠探测的格式不伪造校验通过。
- URL：HTTP/HTTPS、公网无法访问、需登录、短时签名、重定向、私有地址、超时、体积超限、模型绑定的临时 OSS URL。
- 图片 Base64：有效 MIME、无效编码、超大内容；视频/音频/文档 Base64 拒绝。
- 30 秒生成结果再引用：必须先截取为满足 15 秒输入限制的素材，保留原件。

测试数据中的文件大小基准、媒体探测工具版本与时间精度必须写入结果，不能靠浏览器显示的整数时长判断所有边界。

## 5. 账务与任务故障用例

1. 同一用户同时提交多任务，余额刚好够一个、多个或不足；可用与冻结总额始终一致。
2. 相同幂等键连续/并发提交、不同请求体复用同键、前端双击、网络重发。
3. 相同终态重复到达、轮询与回调竞争、Worker 失去租约、应用重启后再次处理。
4. 钱包预占完成但队列暂不可用；上游受理成功但响应丢失；已返回 ID 但持久化失败。
5. 创建结果未知时不得自动切换渠道重新提交；人工核实不重复生成、不重复结算。
6. 价格、折扣、渠道倍率在排队或运行时变化，已提交任务仍按快照结算。
7. 智能时长实际短于预占、用量小数、输入多段视频、音频开关；金额与公式一致。
8. usage 缺失、负数、合计不一致、SR 不一致、实际高于预占，进入差异处理，不静默扣超额。
9. PENDING 取消时恰好变 RUNNING，处理取消失败和后续正常结算。
10. 生成失败不计费；生成成功但保存失败不错误释放全部成本，也不重新调用模型。
11. 管理员重复充值/退款请求、超额退款、扣减冻结金额、并发退款与消费、冲正后再次冲正。
12. 用户退款后，上游成本原记录保留；充值不变成收入，冻结不变成消费。
13. 同一主账号多 Key 共享配额，不越过账号级限制；停用旧 Key 不丢失在途任务。
14. 用户 API 日/月限额按北京时间边界生效；队列等待跨日期的金额归属和预约额度释放明确。
15. 导出、SSE、错误信息中不出现成本、上游密钥、其他用户信息或私有签名 URL。
16. 资产到期与下载/打包/任务提交并发，检查不会在到期后签发新访问地址。

期望金额至少覆盖 WAN3_SPEC.md 第 6.1 节的全部样例，并覆盖 6 位小数舍入和统计聚合。

## 6. 浏览器与视觉验收

使用 Microsoft Edge，自动化采用 Playwright 的 msedge 通道；若环境缺少可用 Edge 自动化能力，先告知用户并选择本机可用替代方案，不能转而依赖谷歌浏览器。

建议覆盖：

- 桌面：1366×768、1440×900、1920×1080。
- 窄屏：1024×768、768×1024。
- 移动：390×844、375×812。
- 100%、125%、150% 系统/页面缩放，长中文标题、很长文件名、极小余额和大金额。

重点截图：登录、管理员双分区、空画布、混合素材画布、各生成模式属性面板、费用展示、结果对比、模型六档价格、余额操作、任务失败/未知、资产到期、移动端抽屉。

不能仅靠截图确认交互。需实际执行键盘选择/焦点、表单提交、滚动、拖拽替代操作、刷新恢复、播放下载和跨页面返回。

画布采用 DOM 节点与成熟画布库时，验收节点、连线、视频首帧和可见区域；不为本项目引入无需求的 3D 场景。

性能基准在测试前固定设备和网络：建议先用 200 节点/300 连线作为常规画布，再用 500 节点进行压力样本。记录拖动/缩放延迟、长任务、内存和视频加载数量。大量不可见节点不得同时解码原视频。

## 7. 真实模型验收与预算

模拟响应用于故障和边界覆盖，不能证明模型实际支持所有组合。

真实验收分层：

1. 两模型 × 三分辨率，验证基本生成、实际返回字段、转存与计费。
2. 文生、首帧、首尾帧、三种单参考、全部混合参考、文件、网页、编辑、前/后/双向延长。
3. audio、seed、prompt_extend、watermark、ratio、duration 的代表性组合及智能时长。
4. 所有支持文件格式与尚不明确的媒体边界；失败/取消行为在可控条件下核实。
5. 在适配矩阵中逐项标明“契约测试通过”“真实调用通过”“待真实验证”，不得混用。

仅两模型六个档位各生成一个 2 秒文生视频，按原价估算为：
2 × (0.30 + 0.60 + 1.20 + 0.45 + 0.90 + 1.80) = 10.50 元。
这只是最小基础样本，完整模式、输入视频、失败重试和存储流量另计，不能当作全部验收预算。

正式真实测试前出具调用清单、预估秒数与费用上限，待用户确认测试预算后执行。费用上限达到时停止新增付费测试，记录尚未覆盖项目；不能把未测项打勾。

## 8. 子智能体代码审查边界

用户只允许子智能体做代码审查：

- 可读取代码、接口、数据库定义、测试结果和变更。
- 可报告缺陷、风险、回归范围、缺失验证与建议方案。
- 不得写实现代码、改文件、提交修复、生成可直接落库的迁移或代替主开发完成模块。
- 审查任务说明必须包含“只读，不改代码”。
- 主智能体核实发现并决定修复，不能不经分析就逐条机械照做。
- 缺陷报告应有文件/行号、可触发条件、实际影响、严重度和证据；不把泛泛优化建议当阻塞缺陷。

开发后的 P8/P9 已使用三名子智能体进行只读审查与复核；实现及修复均由主智能体完成。

## 9. 修复流程

每个缺陷修复前依次完成：

1. 复现并界定预期行为，确定是不是文档、配置、代码或第三方行为差异。
2. 找到根因，画清直接调用链、共享模块和数据影响。
3. 比较候选方案：最小局部修复、共享规则修复或必要的数据修正；解释为何选择该方案。
4. 评估权限、计费、历史数据、画布保存、异步任务、资产生命周期及接口兼容性是否受影响。
5. 列出可能引入的新问题，确定最小充分回归范围。
6. 若改变用户权益/计费规则/删除政策/范围，先询问用户；纯粹恢复已确认行为的常规修复不重复申请批准。
7. 主智能体实施，保留可回滚变更；数据修复单独记录影响行数和回滚/补偿办法。
8. 执行集中回归，确认原故障消失且影响范围无回归，再更新进度与缺陷状态。

对资金类缺陷优先恢复账务一致性，不直接批量改余额；通过有审计的补偿流水纠正。对已经提交的供应商任务不通过重复发送“修复”本地状态。

## 10. 发布门槛

- 权限越权、密钥/成本泄漏、资金错误、不可恢复数据丢失为阻塞发布问题。
- P0/P1 全部解决；影响核心创作、收费或 30 天资产承诺的 P2 也必须解决。
- 全部已承诺首版功能完成，真实调用覆盖与未确认限制有明确说明。
- 没有仍被伪装成成功的转存失败、待核实任务或未核对账务。
- 数据库迁移、首次管理员创建、备份恢复、密钥轮换和 Worker 恢复演练完成。
- 30 天清理先在测试 Bucket 验证，生产生命周期配置不误覆盖已有规则。
- 未解决非阻塞问题向用户说明，并记录是否接受；不能静默交付。
- PROGRESS.md、验收报告、缺陷表与部署说明同步更新。
