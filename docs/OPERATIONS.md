# 部署与运维

## 架构决策

单机部署由一个 Node.js 服务提供 API、静态界面和持久数据库队列。React/Vite 构建静态文件。生产使用 PostgreSQL；本机开发使用兼容 PostgreSQL 的 PGlite。采用显式 SQL 事务、数据库租约和幂等记录，替代最初建议的 Prisma/Redis/BullMQ，减少单机部署组件。任务不依赖进程内队列，重启后继续轮询已知 task_id；提交不明确的任务进入 UNKNOWN。

生产推荐 4 核 8GB 起步，按转码并发和存储规模扩容。FFmpeg 只处理本地临时文件，限制线程及运行时间。不要在生产使用嵌入式数据库或开放开发服务器。

## 必需服务

- 中国大陆 HTTPS 域名，按实际部署完成备案。
- PostgreSQL 16+，数据库账号最小权限，定期备份。
- 私有华北2（北京）OSS，或可被百炼访问的站内 HTTPS 签名素材服务。禁止公开 Bucket。
- 北京百炼 WorkspaceId 及有 Wan 3.0 权限的 API Key。
- SMTP：启用邮箱验证码时必需。

环境变量详见 `.env.example`。首次初始化必须在可信网络内完成，再开放站点。根密钥丢失无法恢复渠道凭据；更换 APP_SECRET 前需用旧密钥解密并重新加密数据库凭据，不能仅替换环境变量。

Docker Compose 使用 `database` 和 `assets` 命名卷；后者保存应用数据和本地媒体，由镜像中的 node 用户拥有。它们与本机 `data/` 目录独立，迁移本机数据前需单独制定 PostgreSQL 导入方案，不能直接复制 PGlite 目录作为 PostgreSQL 数据目录。构建上下文排除测试数据库及日志。需要使用国内可达的镜像仓库时，设置 `NODE_IMAGE` 与 `POSTGRES_IMAGE`；本轮未运行 Docker 部署验收。

## 备份与恢复

每天运行 pg_dump 备份数据库，并备份加密根密钥、配置和本地对象存储（若启用）。OSS 资产按 30 天生命周期保留；平台每日/分钟清理会保留元数据。备份含账号和提示词，仅管理员可访问。

恢复顺序：停止应用 -> 恢复数据库 -> 恢复原 APP_SECRET 与存储 -> 启动同版应用 -> 核对钱包 available/frozen 与 ledger -> 核对 UNKNOWN/SUBMITTING/RECONCILE -> 再开放新任务。不要对已有任务更换渠道原凭据版本。

升级先备份，再停止单机进程并替换构建文件；保留 data 与 .env。回滚代码需先确认 schema 兼容，不能回滚钱包流水。迁移为幂等结构创建，迁移版本在 schema_migrations 记录。

## 账务与故障

余额只由不可覆盖的流水调整。调用冻结、结算、释放均带业务幂等键。调用退款关联原任务且不超过已收未退金额；余额退款从可用余额扣除；冲正引用原人工流水。退款不会改变真实上游成本。

UNKNOWN 不自动重试提交。管理员按上游请求 ID/任务 ID 和官方账单核实后查询、释放冻结或登记实际成本。保存结果失败仅重试下载，不重新生成；上游结果只保留 24 小时，须尽快排查 OSS、网络或用户配额。

同一阿里主账号应填写相同 account_group。每模型最多 5 并发，服务串行提交不超过 5 RPS；查询不超过 20 RPS。单机运行器有数据库租约，避免重复消费。

## 验收边界

本地自动化测试采用隔离 DATA_DIR；禁止把测试用户、充值或素材写入正式数据。真实模型验收需提供渠道、公开素材存储、授权预算，并记录实际模型/分辨率/用量/费用。未提供的服务不能标记通过。
